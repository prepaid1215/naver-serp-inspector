# NAVER Chat Bridge v2.0 beta

## 목표

ChatGPT의 GitHub 연결을 이용해 네이버 검색 요청을 비공개 저장소에 만들고, 사용자가 확장프로그램에서 해당 요청을 실행 승인한 다음 네이버 PC 검색 결과와 공개 블로그·카페 글의 본문을 비공개 저장소로 되돌립니다. ChatGPT는 연결된 GitHub 도구로 결과 파일을 읽습니다.

**이것은 ChatGPT의 내장 웹 검색 도구에 네이버를 추가하는 기능은 아닙니다.** 확장프로그램을 설치하고 연결한 사용자가 요청별로 실행 및 업로드를 직접 승인해야 합니다.

## 1회 준비

1. GitHub에서 기존 소스 저장소와 분리된 **Private** 저장소를 만듭니다. 공개 저장소는 업로드를 차단합니다.
2. GitHub Fine-grained Personal Access Token을 발급합니다. 해당 Private 저장소 한 곳에만 Repository Contents: Read and write를 부여하세요. 토큰을 채팅에 입력하거나 소스코드에 저장하지 마세요.
3. 연결된 GitHub 앱이 해당 Private 저장소를 읽고 요청 파일을 생성할 권한이 있는지 확인합니다.
4. Chrome/Edge에 SERP Lens 베타 확장프로그램을 로드합니다.
5. SERP Lens → **ChatGPT 네이버 검색·본문 연결** → 저장소(소유자/이름), 브랜치(main), 토큰 입력 → 연결합니다.
6. 토큰은 탭의 실행 메모리에만 보관하며, 탭을 닫으면 다시 입력해야 합니다.

## ChatGPT 검색 요청 파일

ChatGPT가 연결된 GitHub 도구로 다음 경로에 새 JSON 파일을 생성합니다:

bridge/requests/<job_id>.json

예시 요청 JSON (실제 생성 시 현재 UTC 시각을 입력):

{
  "schema": "naver-chat-job-v1",
  "job_id": "20261105T093000Z-aabbccdd",
  "mode": "search_and_read",
  "query": "다이소유심",
  "device": "PC",
  "max_articles": 10,
  "requested_at": "2026-11-05T09:30:00Z"
}

요청 ID에는 UTC 날짜+시간과 6~16자리 소문자/숫자를 사용합니다. 7일 초과 요청과 형식 오류는 거절합니다. 본문 개수는 최대 10개로 제한합니다.

## 검색 실행과 ChatGPT로 회수

1. ChatGPT에게 “네이버에서 다이소유심 검색 결과와 블로그 글 최대 10개 조사해 줘”라고 요청합니다.
2. ChatGPT가 Private 저장소에 요청 파일을 생성합니다.
3. 확장프로그램 연결 화면 → 요청 새로고침 → 해당 요청의 **검색·본문 수집 실행**을 누릅니다.
4. Chrome이 네이버 검색·블로그·카페 호스트 접근 권한을 요청하면 승인합니다.
5. 확장프로그램이 네이버 PC 검색 결과를 읽고, 발견된 Naver 블로그·카페 링크를 최대 10개 방문합니다. 외부 도메인으로는 이동하지 않습니다.
6. 추출된 제목·본문·링크를 미리 확인한 뒤 업로드 동의를 체크합니다.
7. **검토한 결과를 GitHub에 전송**을 누릅니다. 이때 다음 경로에 결과가 저장됩니다:

bridge/results/<job_id>.json

8. 이 채팅에서 “수집 결과 분석해 줘”라고 요청하면 ChatGPT가 GitHub 결과 파일을 읽고 분석할 수 있습니다.

업로드하지 않는 경우 추출 결과 JSON을 직접 다운로드하고 채팅에 파일을 첨부할 수도 있습니다.

## 보안 및 정확성

- 결과 전송 전 비공개 저장소인지 다시 검사합니다.
- 토큰은 API 요청 인증 헤더에만 보내고 화면/업로드 파일에 기록하지 않습니다.
- 사용자의 클릭 없이 검색 탭을 열거나 자료를 업로드하지 않습니다.
- 요청 내용으로 임의의 사이트 URL을 방문하지 않습니다. 검색에서 추출한 네이버 블로그·카페만 허용합니다.
- 자동 대량 크롤링, 캡차 우회, 로그인 제한 글 열람 기능이 없습니다.
- 문서별 본문은 최대 15,000자이고 원본 HTML·스크린샷·쿠키는 업로드하지 않습니다.
- 네이버의 동적 로딩이나 iframe 구조에 따라 본문이 누락될 수 있습니다.
- 블로그 글 10개 요청은 최대 수집 시도 횟수이며, 10개 확보를 보장하지 않습니다.
- 검색 파서가 추출한 DOM 순서는 네이버 공식 순위나 비공개 알고리즘 점수가 아닙니다.
- 앱/연결의 권한에 따라 private 저장소 읽기 또는 쓰기가 안 될 수 있습니다.
- 초판은 PC 통합검색과 Naver 블로그/카페 본문만 지원합니다.

## 테스트 계획

JavaScript 단위 테스트는 요청 형식·URL 허용 범위·업로드 경로·Private 저장소 검사·중복 업로드 거부를 확인합니다. Chromium 오프라인 테스트는 GitHub REST 모의 응답, 사용자 검색 실행 승인, 결과 검토·전송, Naver 형태의 게시글 본문 추출을 검증합니다.

실제 네이버/실제 GitHub Private 저장소 연동은 사용자의 설치·승인 후 별도 현장 검증이 필요합니다.
