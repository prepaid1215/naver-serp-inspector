# 블로그 영역 미식별 원인 진단 — 2026-11-12

## 결론

기본 검색어 4개(`KT바로유심`, `LG모두의 원칩`, `태블릿소유자회원번호`, `다이소 유심`)를 모바일 에뮬레이션(390×844)으로 DOM 수준에서 다시 확인했다. 추출기 결함이 아니라 **네이버가 블로그를 독립 영역으로 묶지 않고 게시글별 카드로 통합 피드에 섞어 노출**하는 구조다(원인 분석 3번에 해당).

| 확인 항목 | 결과 |
|---|---|
| "블로그"/"VIEW" 제목 요소 | 4개 검색어 모두 없음. 제목 요소는 `이미지`(H2)뿐 |
| 블로그 글 DOM 구조 | 글 하나가 최상위 `.api_subject_bx` 카드 하나(작성자 프로필 + 제목 + 본문). 카드당 글 1개 |
| 카페 글과의 관계 | 같은 피드에서 카페 카드가 블로그 카드 사이에 끼어 노출(예: `KT바로유심`은 블로그 5개 → 카페 2개 → 블로그 4개 → 카페 1개 → 블로그 1개) |
| 블로그 카드 수 | 한 화면에서 10개를 넘음(검색어당 11~16개). 10개 경계를 정의하는 컨테이너 없음 |
| AI 브리핑 | `LG모두의 원칩`, `태블릿소유자회원번호`에서 상단 AI 브리핑 카드가 블로그 글 3개를 인용. 피드 결과가 아님 |

따라서 "통합검색 블로그 영역 TOP10"이라는 지표는 현재 이 검색어들에서 **정의할 수 없다**. 임의 경계를 만들지 않았고 `INTEGRATED_BLOG_SECTION_TOP10`은 `UNKNOWN`/`SECTION_NOT_PRESENT`를 유지한다.

## 코드 결함 하나 수정 (`automation/extractor.py`)

기존 추출기는 `#main_pack` 안의 모든 블로그 링크를 화면 위치순으로 모았다. 이 방식은 AI 브리핑이 인용한 글 3개를 후보 순위 1~3위에 끼워 넣고, 카드 하나에서 여러 링크를 중복 후보로 잡을 수 있었다. 이제:

- 최상위 `.api_subject_bx` 카드 단위로 카드당 첫 블로그 글만 채택
- AI 브리핑·광고 카드 제외
- 카드 구조가 없으면 기존 방식으로 대체
- `feed_layout`, `feed_interleaved_cafe_cards`를 근거로 기록, 사유 문구를 구체화

`INTEGRATED_BLOG_ARTICLES_TOP10`은 계속 `CANDIDATE`이며 VERIFIED로 승격하지 않는다. `LG모두의 원칩` 실측: 수정 전 후보 1~3위는 AI 브리핑 인용 글, 수정 후 후보는 피드 카드 순서(연진이통신 → e심전심 → …).

## 대체 지표 비교 (운영자 선택 필요)

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 통합검색 피드 내 블로그 카드 순번 (현재 `ARTICLES_TOP10`) | 실제 화면 노출 순서와 일치, 자동 수집 가능 | 영역 TOP10이 아님. 카페 카드가 끼어 순번이 흔들림. 검색 시점마다 변동 큼 |
| B. 피드 전체 순번(카페 포함) | 사용자가 실제로 스크롤하는 위치를 반영 | 카페 노출에 의해 블로그 순번이 변동 |
| C. 블로그 탭(`where=blog`) 순위 | 블로그만의 명확한 순위 목록 | 통합검색 노출과 다른 지표. 별도 수집·검증 필요 |
| D. 미노출/노출 여부(상위 N 카드 내 포함) | 노이즈에 강함 | 순위 정밀도 없음 |

스펙(11절)대로 정책 변경은 자동 적용하지 않았다. 어떤 대안을 배정 기준으로 쓸지는 운영자가 정해야 한다.
